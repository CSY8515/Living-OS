# Visual Language

## Character

Living OS is calm, alive, precise, and personal. It may feel futuristic, but it
must not become a neon control panel or an AI-generated pattern collage.

## Color

- Use one primary accent family for actionable focus.
- Build most surfaces from deep neutral values.
- Reserve semantic red, amber, and green for actual state.
- Purple may provide restrained atmospheric depth, not compete with the primary
  accent.
- Never encode status by color alone.

Exact tokens must be sampled and approved from registered official Concept Art
before the future full UI implementation.

## Light and material

- Lighting follows a believable source and direction.
- Glow is local, soft, and subordinate to text contrast.
- Glass communicates layered depth only when the background supports legibility.
- Metal communicates structure and precision.
- Natural material communicates life and growth.
- Avoid repeated particles, identical lens flares, arbitrary circuit lines, and
  other recognizable AI-image filler patterns.

## Type and text

- Use a small, consistent hierarchy: display, title, body, supporting text.
- Text is reduced by improving composition, not by hiding necessary explanation.
- Numbers use stable alignment where comparison matters.
- Decorative uppercase labels remain short.

## Charts

- Minimize grid lines and competing colors.
- Highlight one decision-relevant series.
- Always provide labels, units, time range, and an accessible text equivalent.
- Do not imply causation from visual correlation.

## Cross-device continuity

Desktop, notebook, tablet, and mobile use the same objects, materials, tokens,
and state language. Responsive layouts recompose the world; they do not become
an unrelated mobile theme.
